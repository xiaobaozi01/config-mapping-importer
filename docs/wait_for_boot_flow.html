Boot Readiness

ConsoleSession
wait_for_boot()

它等待的不是“设备安静”，而是“login 提示符已经出现，并且 console 对空行有响应”。 下面的时间线解释稳定窗口、空行探测和 Auto Image 持续输出之间的关系。

只认 login 窗口 BOOT_READY_SETTLE = 1.0s 探测 一个空行 不依赖 FIPS 不要求 输出安静 行缓冲 CRLF / LF / CR

01一句话解释稳定窗口

“稳定”指候选提示符被识别后保持了 1 秒，不是终端 1 秒没有输出。

_boot_ready() 只看： candidate_at is not None and now - candidate_at >= BOOT_READY_SETTLE。 它不检查 last_data_at，所以 Auto Image 持续输出不会重置窗口。

不是安静窗口

不需要“最后 1 秒没有新数据”。只要 login 在 1 秒前已经被识别， 即使这 1 秒内一直有 Auto Image，窗口也会到期并发送探测。

为什么还要等 1 秒

给跨包的提示符、尾随日志和终端刷新留出时间；避免刚看到一个疑似 login 片段 就立刻发空行。

02一次成功启动的时间线

示例时间：t=0 看到 login，1 秒后探测，探测后再次看到 login，再过 1 秒返回。

login / 新提示符 空行探测 Auto Image 持续输出
关键：Auto Image 只是在 candidate_at 之后继续写日志。 它不会把 candidate_at 清空，所以 1 秒窗口照样到期，探测照样发送。

03状态怎么流转

wait_for_boot 本身不登录，只负责等到“可交互的 login”。

WAIT_LOGIN→ CANDIDATE→ SETTLE 1s→ PROBE→ WAIT_NEW_LOGIN→ SETTLE 1s→ RETURN

主循环

  1. 1读取一个 chunk，追加到 state.output。
  2. 2识别最后一条有效行；只有 boot_prompts 里的提示符才算候选。
  3. 3候选第一次出现时记录 candidate_at，之后不清空。
  4. 4窗口到期后发一个空行，清空 pending_line 和 candidate_at。
  5. 5只看 probe 之后的新输出；再次出现 login 才进入第二个窗口。
  6. 6第二个窗口到期后返回累计的完整启动回显。

代码骨架

deadline = now + timeout

while loop.time() < deadline:
    chunk = await self._read_text()
    if chunk:
        self._process_boot_chunk(state, chunk, now)

    if self._boot_ready(state, now):
        if not state.probe_active:
            state.probe_active = True
            state.candidate_at = None
            state.pending_line = ""
            await self._nudge()
            continue
        return state.output

    if self._boot_should_nudge(state, now):
        await self._nudge()

    await asyncio.sleep(self.READ_INTERVAL)
启动阶段不再用字符 offset： _split_terminal_lines() 处理 CRLF、LF、CR， 未完成行保存在 pending_line；探测时清空它， 只接受探测后的新行，避免旧半行被当成响应。

04Auto Image 洪泛时会怎样

持续输出本身不是问题；提示符被挤出窗口才是问题。

持续输出不会重置窗口

_boot_ready() 只看 candidate_at。 Auto Image 更新的是 last_data_at，只影响主动 nudge 的时机， 不影响稳定窗口是否到期。 

return (
    state.candidate_at is not None
    and now - state.candidate_at >= self.BOOT_READY_SETTLE
)

真正需要防的是提示符丢失

启动阶段现在按完整行处理：CRLF、LF、CR 都能分行，未完成行留在 pending_line，不会被字符切点截断。 通用命令分析仍先 normalize 全文，再从后往前跳过 Auto Image 和噪声。

login 后大量 Auto Image仍能找到 login
探测后 Auto Image 包围 login仍能识别新 login
Auto Image 不匹配 background不会被跳过，需要补 pattern
设备完全不响应空行仍会超时，属于设备行为

05边界与失败

不会提前返回

  • 1只出现 shell/exec 片段，不匹配 boot_prompts。
  • 2login 只出现一次，空行探测没有新 login。
  • 3探测后只有 Auto Image，没有提示符。
  • 4旧 login 位于 probe 之前，不会被再次使用。

超时与恢复

  • 1启动阶段断线：最多重连 MAX_RECOVERIES=3 次。
  • 2重连后清空 candidate_at，必须重新看到 login。
  • 3超时抛 TimeoutError，错误只带最后 4000 字符。
  • 4成功后返回完整启动回显，交给 enter_command_prompt() 登录。
