01总编排：import_cfg

导入和初始化不设整体超时；入口模式切换和恢复单次最多 300 秒，历史最多查询 60 次、每次最多 10 秒。

入口

import_cfg(local_cfg_path)

直接执行导入流程，不设总超时；异常或外部取消后，finally 中统一 cleanup。

连接

init_telnet_client()

通过父类取得 TelnetClient，连接过程不再受入口整体超时限制。

当前状态

enter_command_prompt()

识别 login、password、shell、EXEC 或配置提示符，按需登录和切换；已在配置模式则直接继续，随后 top 返回顶层。

关闭自动升级

_disable_auto_image_upgrade(session)

检查 root 认证后，执行 top 和 delete chassis auto-image-upgrade，单独 commit 并核实历史；成功后再准备 FTP。

父类能力

FTP 准备

直接调用父类：创建临时 FTP 节点、上传 cfg、连接倒数第二个适配器。

Parent Methods

init_ftp_server()创建临时节点
copy_file_to_ftp_server()上传本地 cfg
link_ftp_server()连接数据口
Prep

_prepare_config(session)

准备命令必须成功，失败时停止导入并清理。

top
set chassis fpc 0 pic 0 number-of-ports N
set interfaces <if> ... address 10.0.0.2/24

准备命令全部执行后统一 commit，并核实提交历史。

Load

_load_config(session)

发送 load override ftp://...，最多恢复后重试 3 次。

成功只认 load complete；非零 error count 直接失败；无 complete 则失败或恢复。

Commit · Final

_commit_and_verify(session, "final")

生成独立 UUID；commit complete 只是候选成功，最终以 show system commit 最新已完成记录为准。

finally

_cleanup(ftp_server, telnet_client)

删除 FTP 节点、关闭 Telnet、处理最后适配器自环；三者独立捕获异常，不覆盖原始失败。

分支：init_device() — 不走 FTP；进入配置顶层和 root 认证检查后，先单独关闭自动升级并核实提交，再执行 top、 set system host-name、 set chassis fpc 0 pic 0 number-of-ports 40。 主机名和端口配置统一提交；各阶段失败会直接向上抛出。

02入口与模式切换

import_cfg 可以在设备启动后反复调用，从当前提示符开始处理，不要求设备重新启动或返回 login。

从任意已支持模式进入

  1. 1读取 chunk，累计到会话的 _buffer，跨包提示符继续拼接。
  2. 2_expect() 从 profile 的全部提示符规则识别当前状态。
  3. 3未收到提示符且持续静默时，每 3 秒发送空行请求当前提示符。
  4. 4按当前状态发送认证或模式命令，已经在配置模式时直接返回。
  5. 5业务层先执行 top，确保 root 认证查询和后续配置从顶层开始。
  6. 6模式切换入口单次限时 300 秒，内部重连不重新包装超时。
统一入口：导入和初始化直接从当前提示符进入；NUDGE_INTERVAL 统一控制登录和命令交换的静默探测间隔。

enter_command_prompt()

按 profile 的 login_actions 和 mode_steps 驱动：

login→ password→ shell→ exec→ config
  1. 1login 提示 → 发送 root。
  2. 2password 提示 → 发送 admin123。
  3. 3shell 提示 → 发送 cli。
  4. 4exec 提示 → 发送 configure。
  5. 5同一提示符最多重试 MAX_RECOVERIES=3 次。
  6. 6断线则重连、清空旧 buffer，再重新走状态机。

03命令交换与文本定位

命令结果不是靠“在整段回显里搜字符串”，而是先隔离，再按用途做锚定匹配。

会话缓冲区与命令交换

ConsoleSession._buffer 保存尚未消费的原始数据。 _read() 统一追加数据，_expect() 等待目标提示符并返回名称、原始边界和稳定起点， _consume() 取走本次处理的前缀，剩余数据保留给下一阶段。 是否消费数据由调用方决定；命令回显过滤、成功标记、宽限期和恢复状态由 _wait_command_result() 判断，通用等待函数不接收命令或成功标记参数。 启动、登录和命令交换共用等待逻辑的静默探测： 无提示符且连续静默 3 秒时发送回车，持续有输出或等待提示符稳定时不探测。 清理残留回显时不启用探测；启动流程先消费候选提示符和探测前的数据，再回车等待新的响应。 同一会话按顺序执行操作，每次返回的结果都是独立快照。

  1. 1ensure_ready()：先 drain 残留；若停在非 command prompt 或断线，先 restore。
  2. 2发送一次完整命令行；result.sent 标记是否真正写出。
  3. 3持续读取 chunk，追加到会话缓冲区，不向业务流程传递可变读取状态。
  4. 4每次新 chunk 都检查期望提示符、非期望提示符和 success pattern。
  5. 5提示符出现后至少等 PROMPT_SETTLE；有 success pattern 时再给宽限。
  6. 6消费到匹配边界并返回 ConsoleResult；后续日志保留在缓冲区，超时或断线的部分输出仍交给调用方。

analysis_text() 流水线

raw output命令 echo、输出、日志、prompt
→
normalizeANSI、退格、CRLF、NUL
→
_strip_command_echo行级删除第一条匹配 echo
→
逐行过滤空行、background、[edit ...]、prompt
→
analysis_text只用于结果判断的文本
prompt_last_meaningful_line() + 有序 prompt 规则；只看最后有效行。
successload complete / commit complete；锚定行首。
error^error:；跳过 warning、background 和 ignore_pattern。
history按记录正则解析 index/time/user；pending 和 comment 单独处理。

残留输出

ensure_ready() 在每条命令前 drain 残留，最多 2s / 安静 0.3s。 残留只打 debug 日志，不并入下一条命令结果；若残留停在 command prompt，直接认为就绪。

第一条 echo

只删除第一条“整行等于命令”或“prompt + 命令”的行；后面的相同文本保留， 避免误删设备真实输出。普通输出行末尾碰巧出现命令文本时不会删除。

04Commit 状态机

commit 一旦发出，不自动重发；只有明确锁拒绝才重试同一 UUID。

Start

生成 comment = cfg-import-<UUID>

提交命令不限时等待提示符、会话丢失或外部取消；之后按固定次数核实历史，每次查询独立限时。

未发出

result.sent == False。恢复会话，最多 3 次。

仍失败 → 未确认
锁拒绝

明确 locked 且 prompt 已回后，每隔 5s 重试，首次提交之外最多 60 次；使用同一 comment，恢复不重置次数。

次数耗尽 → JunosCommandError，保留最后一次锁错误原文
明确失败

^error: 或 configuration check-out failed。

立即失败，不查历史
结果不明

commit complete、lost、ambiguous。

查 show system commit
History

_verify_commit_history()

解析最新已完成记录；comment 必须与本次 UUID 完全一致。 pending 不算完成；旧记录、echo 里的 UUID、comment 里的 error 都不算成功。

match

最新已完成 comment == UUID。

成功
mismatch

可读，但不是本次。

验证失败
no records / unreadable

无法确认。

未确认
prep commit

同样必须核实成功。

失败则停止导入
重试次数与 commit：提交本身不设超时；历史最多查询 60 次，间隔 5 秒，每次查询最多 10 秒， 包含该次就绪检查。锁冲突最多重试 60 次，间隔 5 秒；恢复不重置次数，最后一次失败后不再等待。 不再传递总截止时间，实际总耗时包含命令和恢复耗时，可能超过 300 秒。 已发送的提交仍不限时等待，结果不明时只恢复并核实历史，不重复提交。

05一次导入的时序

成功路径；失败会在对应节点向上抛，finally 仍执行 cleanup。

01 Caller→ Manager import_cfg(path)
02 Manager→ Console enter_command_prompt()
03 Console→ Junos 读取当前提示符；静默时每 3 秒发送空行探测
04 Manager→ Console 按需登录并切换至配置模式；已在配置模式则直接继续
05 Console→ Junos top → 检查 root 认证 → 单独提交关闭自动升级并核实
06 Manager→ FTP init_ftp_server → copy_file → link_ftp_server(adapter)
07 Manager→ Console _prepare_config：top / ports / IP；统一 commit 并核实历史
08 Manager→ Console _load_config：load override ftp://...
09 Console→ Junos load complete (N errors) / error / prompt
10 Manager→ Console _commit_and_verify("final", remaining)
11 Console→ Junos commit comment "cfg-import-<UUID>" → show system commit
12 Manager→ FTP finally：delete FTP node / close Telnet / loopback
